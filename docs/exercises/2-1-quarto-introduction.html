Ex-2-1: Quarto Documents and Rendering, with an AI Assistant

Abstract
Quarto

This is an in-class exercise. Before class, work through the lecture 02-1: Quarto Documents and Rendering. In class, you work through the worksheet with an AI assistant writing the code. Your job is everything the AI cannot do: knowing what the data contains, deciding what the reader must see, and judging the result in the rendered HTML.

Setup

  1. Download the worksheet, ex-2-1.qmd, and the data file 2-1-nebraska-yield.csv.
  2. Make an R Project folder called ch2-practice, with two subfolders, data and analysis. In RStudio: File, New Project, New Directory, New Project. You may ask the AI how to make the subfolders.
  3. Copy 2-1-nebraska-yield.csv into ch2-practice/data, and the worksheet into ch2-practice/analysis.
  4. Open the worksheet and render it once before you start.
It worked if

Rendering the blank worksheet makes ex-2-1.html next to it, with the heading “Task 1: Look at the data”. Do not read “The AI’s report” in the HTML yet; Task 2 asks you to predict it.

If the render stops with an error about the file not existing, type here::here() in the Console: it should print the path to ch2-practice and nothing longer. If it prints a path ending in analysis, the .Rproj file was not recognised. here only accepts a .Rproj file whose first line starts with Version:, which every project created in RStudio (File, New Project) has. An empty .Rproj file made any other way does not count.

Answers

Open each one only after you have tried the task.

Task 1: Look at the data

What you should find

A. 226 lines: one line of column names and 225 data rows.

B. 2014 to 2018, 5 years.

C. One county in one year. There are 69 counties, but not every county has a row in every year: 2014: 51, 2015: 48, 2016: 50, 2017: 47, 2018: 29.

D. No. county_code is written with leading zeros (001, 003), so it is a code, not a quantity. read_csv() keeps it as text here, but read.csv(), which AI assistants often write, would turn 001 into 1. Nothing in this exercise uses that column; Lecture 03-1 is about exactly this.

Task 2: Read the AI’s report before rendering it

What you should find
Chunk Runs? Code shown? Result shown?
read-yields yes yes nothing to show
drop-year yes no no (include: false)
by-year yes yes yes
overall yes yes yes

B. Only 2014 to 2017. The hidden chunk drop-year removes 2018 before the table is made.

C. No. The sentence’s 198.6 is typed, not computed, so nothing ties it to the number printed above it.

Task 3: Render and judge the report

What you should find

Three problems:

  1. A step is hidden. The table shows 4 years, but the file has 5. A reader who looked at the data, as you did in Task 1, can see from the HTML that a year is missing; the HTML does not say why. Only the .qmd shows the drop-year chunk, which has no sentence above it, only an R comment.
  2. The sentence disagrees with the result above it. overall prints 201.5; the sentence says 198.6. A careful reader of the HTML can see this one.
  3. The sentence says “2014 to 2018”, while the average covers 2014 to 2017. A reader can see this only by comparing it with the table.

Whether the sentence was typed or computed cannot be seen in the HTML at all: the two look identical. You need the .qmd.

The decision about the data. Dropping 2018 is a choice, not a mistake: that year has only 29 counties, against about 50 in the others. There can be good reasons to drop it or to keep it. It is your choice, as the person responsible for the analysis, not the AI’s, and whichever you choose, it must be visible in the HTML with a sentence saying why.

Task 4: Ask the AI to fix the report

What you should find

If you kept every year: yields has 225 rows, years 2014 to 2018, and the last sentence reads 203.0 bushels per acre.

If you kept the step that drops 2018: 196 rows, years 2014 to 2017, the step now visible with a sentence, and the last sentence reads 201.5 and says “2014 to 2017”.

Either way, in the .qmd the number in the last sentence should now be written as inline R, for example `r round(mean(yields$corn_yield), 1)`. In the HTML it looks exactly as a typed number would, which is why the check means opening the .qmd.

The blanks of the request, filled in for the first choice:

Remove the chunk that drops 2018.
...
Check the number of rows in yields (I expect 225) and the years it covers
(I expect 2014 to 2018).

Task 5: Works at the Console, fails on render

What you should find

Step 3 printed a number, because the green button runs the chunk at your Console, where yield_goal exists. Step 4 stopped with:

Error:
! object 'yield_goal' not found
Quitting from ex-2-1.qmd:...-... [task-5]

(the line numbers depend on your file). Rendering starts a new R session, which has never seen yield_goal.

The fix is a line yield_goal <- 200 in a chunk inside the document, above task-5 or in it. After rendering, the count is 145 county-years if you kept every year in Task 4, or 120 if you kept the step that drops 2018.

If the AI’s fix was to tell you to type something at the Console again, it did not fix the document. The test is the render: it starts from nothing, so it shows whether the document works without your Console.

Task 6: Send the HTML

What you should find

The first copy, on its own, is missing the figure, and it also opens without its styling. Rendering wrote the figure into a folder ex-2-1_files/ next to the HTML, and the HTML only points at it. Copied away from that folder, it has nothing to point at.

With embed-resources: true, written under html: like this:

format:
  html:
    embed-resources: true

the figure and the styling are packed into the HTML file itself. The second copy shows everything. This is the version to send to an advisor or a coauthor, or to submit.

Note that format: html on one line has to become the three lines above: html turns from a value into a group with a setting under it.

Wrap-up

What a good answer looks like

A. That the number in the last sentence was typed, or what the hidden drop-year chunk did and why. The HTML showed that a year was missing, but not which step removed it or why.

B. The green button runs the chunk at your Console, where anything you typed earlier still exists. The render starts from nothing. Only a render tests the document. To find a missing step before rendering: Session, Restart R, then Run, Run All, which runs every chunk at your Console as a render would.

C. For example: which years the data covers, so a missing year can be noticed; whether dropping a year is acceptable for your question; that the goal is 200 bushels per acre; who will read the HTML and whether it will be sent on its own.
