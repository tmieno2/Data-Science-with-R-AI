Ex-3-1: Getting Data In and Out, with an AI Assistant

Abstract
Data Wrangling

This is an in-class exercise. Before class, work through the lecture 03-1: Getting Data In and Out of R. In class, you work through the worksheet with an AI assistant writing the code. Your job is everything the AI cannot do: knowing what the files contain, asking for the right thing and the right checks, and judging whether the result is right.

Setup

  1. Clone https://github.com/tmieno2/data-science-course-supplementary-datasets if you have not already.
  2. Download the worksheet, ex-3-1.qmd, and the data file corn_messy.csv.
  3. Make an R Project folder called ch3-practice, with two subfolders, data and analysis. You may ask the AI how to do this.
  4. Copy corn_yields.csv, corn_yields.xls and corn_messy.csv into ch3-practice/data, and the worksheet into ch3-practice/analysis.
  5. Open the worksheet and start at Task 1.
It worked if

Typing here::here() in the Console prints the path to ch3-practice and nothing longer.

Answers

Open each one only after you have tried the task.

Task 1: Look and predict

What you should find

A. 162 lines: one line of column names and 161 data rows.

B. 9 columns: Year, State, FIPS, County_name, State_name, Commodity, Data item, Irrigated, Yield. County_name, State_name, Commodity and Data item are text; the rest are numbers. Data item has a space in its name.

C. One county, one year, and one irrigation status (Irrigated is 0 or 1), so most counties appear twice.

D. Two sheets, corn_yields_08 and corn_yields_09.

Task 2: Read the csv

What you should find

161 rows and 9 columns, no missing values, and yields from 103 to 204 bushels per acre.

The checks, and why. The five from the lecture, each tied to a way this import could go wrong:

  1. Rows and columns: a title line read as data, or the reader stopping early, changes the count from the 161 you counted.
  2. Type of every column: Yield read as text would make every later calculation fail or mislead.
  3. Missing values per column: a column that failed to read shows up as all missing.
  4. Range of Yield: a code such as -999, or a number in the wrong units, shows up as an impossible value.
  5. The first row: shifted columns show up when compared with the first data line of the file.

A request that gets all of this in one go:

In my R project, data/corn_yields.csv is a csv file with a header row and
161 data rows (Nebraska corn yields by county and irrigation status).
Read it into a table called corn using readr, building the path with
here::here(). Do not use setwd() or an absolute path. Then print the
number of rows and columns, the type of every column, the number of
missing values per column, the range of Yield, and the first row.

Task 3: Both sheets of the Excel file

What you should find

161 + 161 = 322 rows. Year is 2008 in one sheet and 2009 in the other.

The check from knowing the data. Yields change from year to year, because the weather does, so each county’s yield should differ between the two years. Asking “is each county’s yield the same in both years?” gives TRUE: every county has exactly the same yield.

That cannot be real data. The code is fine; the file is wrong, and no change to the code fixes it. The right move is to stop and ask whoever produced the file, and not to analyse year-to-year changes until you have an answer.

This is the point of the task: the row count and the types all passed. Only a check you thought of, because you know something about corn, caught the problem.

Task 4: A messy file

What you should find

4a, the short request. Plain read_csv() treats the first description line as the column names, so you get 94 rows and only 3 columns with sentence fragments for names, plus a warning about parsing problems. Base R’s read.csv() stops with an error instead. Either way the problem is visible, which is the good case.

4b, the file. Two lines of description sit above the column names. Missing yields are written two ways, -999 and ., and the second description line says so. county_fips holds 5-digit county codes, and the 5 Colorado codes start with 08. There are 95 lines, so 92 data rows.

4c, a correct result. 92 rows, 5 columns, county_fips is text with the leading zeros kept, yield is a number, 5 yields are missing, and the rest run from 102 to 199. Average yield: 157.7.

The checks, and the problem each one catches in this file:

  1. Rows: the description lines read as data.
  2. Type of county_fips: the leading 0 of the Colorado codes lost.
  3. Type of the yield column: text instead of a number, because of the . entries.
  4. Number of missing yields: should be 5. Fewer means a missing-value code was kept as a value.
  5. Range of yields: a minimum of -999 means the -999 code was not recognised.

The silent trap. If your request mentioned . but not -999, the yield column is a number, nothing errors, and the average comes out at 119.2. Checks 4 and 5 both catch it.

Task 5: Maria’s code

Answers

A. Read the file, skipping the two description lines and treating . as missing; rename the fifth column to yield; average the yields, ignoring missing ones.

B. The path. C:/Users/maria/Downloads exists only on Maria’s computer.

C. First, -999 is not treated as missing, so the average is 119.2 instead of 157.7. Second, read.csv() reads county_fips as a number, so 08125 becomes 8125. Nothing uses that column here, but the first time Maria joins this table to another one by county code, the Colorado counties will quietly fail to match.

D. “Print the smallest and largest yield”: a minimum of -999 is impossible. “Print the type of every column”: county_fips should be text, because it is an ID, not a quantity.

Task 6: Save and read back

What you should find

The rds file comes back identical. The csv file comes back with state_name as plain text rather than a factor, because a csv stores only text and the reader has to guess types again. This is why the lecture recommends rds for results you will read back into R.

If the AI compares with all.equal(), the csv comparison prints several lines starting with Attributes: before the one that matters, Component "state_name": 'current' is not a factor. The Attributes lines are about hidden bookkeeping that read_csv() attaches to every table it reads, not about your data. Ask the AI which lines are about the data itself if this is unclear.

Task 7: Does it run anywhere?

What you should find

If it fails on your neighbour’s computer, the error names the line that depended on your machine, almost always a path. Ask the AI to fix that line, explaining what failed, and try again. A worksheet that renders on someone else’s computer unchanged is the final check that every path in it is relative to the project.
