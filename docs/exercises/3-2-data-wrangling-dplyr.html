Ex-3-2: The Core Operations of Data Wrangling, with an AI Assistant

Abstract
Data Wrangling

This is an in-class exercise. Before class, work through the lecture 03-2: The Core Operations of Data Wrangling. In class, you work through the worksheet with an AI assistant writing the code. Your job is everything the AI cannot do: knowing what the data contains, asking for the right thing and the right checks, and judging whether the result is right.

Setup

  1. Use the ch3-practice project from Ex-3-1. If you do not have it, make an R Project folder called ch3-practice with two subfolders, data and analysis (you may ask the AI how).
  2. Download the worksheet, ex-3-2.qmd, and the data file 3-2-county_crops.csv.
  3. Copy 3-2-county_crops.csv into ch3-practice/data, and the worksheet into ch3-practice/analysis.
  4. Open the project, open the worksheet, and start at Task 1.
It worked if

Typing here::here() in the Console prints the path to ch3-practice and nothing longer.

The data file is a teaching dataset: county yields and drought weeks for Colorado, Kansas and Nebraska, 2000 to 2018, compiled from US Department of Agriculture yields and the US Drought Monitor. No value in it has been changed; the county names were added and weeks_severe_drought adds up three Drought Monitor categories.

Answers

Open each one only after you have tried the task.

Task 1: Read and look

What you should find

A. 1956 rows. One row is one county in one year.

B. Colorado (154 rows, 16 counties), Kansas (534 rows, 56 counties), Nebraska (1268 rows, 82 counties). The names are written with a capital first letter and the rest in lower case. Counties do not all have every year: Nebraska’s 82 counties over 19 years would be 1558 rows, not 1268.

C. Only soy_yield: 856 missing values, 44% of the rows. Every other column is complete.

Task 2: Keep rows

What you should find

Prediction. At most 82 rows, one per Nebraska county, since one row is one county in one year. Only Nebraska and 2012 in the result.

Result. 64 rows: not every Nebraska county has a 2012 row. Kept plus dropped is 64 + 1892 = 1956, so no row was lost on the way, which is what you expect when the condition’s columns have no missing values.

The blanks, filled in: one row is “one county in one year”, the state is Nebraska (not NEBRASKA or nebraska), and you expect at most 82 rows.

Task 3: Split the rows in two

What you should find

Prediction. Every row has a soybean yield that is either below 40 or not, so the two tables together should have all 1956 rows.

Result. 26 + 1074 = 1100. The check fails by 856 rows, exactly the number of missing soybean yields from Task 1. A missing value is neither below 40 nor at least 40, so filter() drops those rows from both tables, without a message.

Nothing is wrong with the code. If your prediction was all 1956 rows, the check is what showed it was wrong. In a request that uses soy_yield, say what should happen to the rows where it is missing.

Task 4: Create a column

What you should find

Prediction. Between 0 (no week in severe drought) and 100 (all 23 weeks). For a row with weeks_severe_drought of 14, the value is 14 / 23 × 100 = 60.9.

Result. From 0 to 100, no missing values. 16 county-years spent the whole season in severe drought or worse.

The blanks, filled in: a column name of your choice, such as pct_severe_drought, equal to “weeks_severe_drought divided by 23, times 100”; range 0 to 100; 0 missing values.

If your hand calculation does not match, check whether the AI divided by 23 or by something else, such as 52 weeks in a year. The range check alone would not catch that: dividing by 52 also gives values between 0 and 100.

Task 5: Summarise by group

What you should find

Prediction. 3 rows, one per state; the numbers of rows add up to 1956. From Task 1, the soybean averages may be a problem, since soy_yield is often missing.

Result.

state_name avg_corn avg_soy rows soy_non_missing
Colorado 168.3 NaN 154 0
Kansas 173.1 50.7 534 185
Nebraska 181.7 55.8 1268 915
  • The corn averages rest on every row and can be reported as they are.
  • Colorado has no soybean yields at all: soy_non_missing is 0, and the average shows as NaN (“not a number”, the average of nothing). Without na.rm = TRUE it would show NA. Report no soybean average for Colorado.
  • Kansas’s soybean average rests on 185 of its 534 rows (35%). The number is a real average, but of a minority of Kansas county-years, likely the counties where soybeans are grown. Report it with that note, or not at all. Nebraska’s rests on 915 of 1268 rows.

This is why the request asked for the number of non-missing values behind each average. Without it, the three soybean averages would look equally trustworthy.

Task 6: Sort

What you should find

The first rows:

state_name county_name year corn_yield weeks_severe_drought
Colorado Bent 2003 0 14.5
Colorado Elbert 2002 0 22.0
Kansas Rawlins 2002 80 21.9
Kansas Greeley 2002 85 22.0
Colorado Bent 2002 90 22.0

2 county-years have a corn yield of exactly 0: Bent 2003 and Elbert 2002, both in Colorado. The next lowest is 80. A yield is harvest divided by harvested area, so a county with a harvested area should not have a yield of 0, even in the 2002 drought; a total failure usually means the area was not harvested and no yield is reported. These two values are most likely a code for “no harvest” stored as a number, much like -999 in Ex-3-1.

Before averaging corn yields, decide what these rows mean, ideally by asking whoever produced the data, and say in the .qmd what you did (for example, treat them as missing). Treated as missing, they would move the Colorado corn average in Task 5 from 168.3 to 170.5; in an analysis of how drought affects yield, two values of 0 count for far more than two ordinary rows.

Sorting is the simplest of the five operations, and here it was the one that found a problem: the top of a sorted column is where impossible values show up.

Task 7: Sam’s code

Answers

A. “Take crops, then keep the rows where state_name is nebraska and the year is 2010 or later, then group by county name, then add each county’s average corn yield to each of its rows, then sort from the lowest average up.”

B. A table with no rows. The state is written Nebraska, with a capital letter, so nothing equals "nebraska". Every later step works on an empty table without complaint. A check of the rows after the filter (expected about 82 counties times 9 years) would catch it.

C. mutate(). It keeps every county-year row and writes the county’s average on each. For one row per county, it should be summarise().

D. County names are not unique across states: 15 names appear in more than one state, for example Cheyenne, Greeley, Hamilton. Grouping by county_name alone puts, say, Lincoln County in Colorado and Lincoln County in Nebraska into one group and averages them together. Group by state_name and county_code (and keep county_name for reading). A check of the number of groups against the number of counties from Task 1 (154) would catch it: grouping by name alone gives 137.

E. The AI usually spots the lower-case nebraska if you mention how the state is written; without that, it can only guess, since it has not seen the data. Whether it raises mutate() against summarise() depends on whether it reads “average of each county” as one row per county. Treat its answer as something to check.
