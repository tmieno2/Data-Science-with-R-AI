Ex-2-4: Articles with Quarto, with an AI Assistant

Abstract
Quarto

This is an in-class exercise. Before class, work through the lecture 02-4: Articles with Quarto. In class, you work through the worksheet with an AI assistant writing the note. Your job is everything the AI cannot do: deciding the claims and what supports each, making sure every reference exists and says what you cite it for, and reading the output for the mistakes that render without an error.

Setup

  1. Use the ch2-practice project from Ex-2-1. If you do not have it, make it as described there.
  2. Download the worksheet, ex-2-4.qmd, and the reference file, 2-4-references.bib, into ch2-practice/analysis. If 2-1-nebraska-yield.csv is not in ch2-practice/data yet, download it there.
  3. Open the worksheet and start at Task 1.
It worked if

ch2-practice/analysis holds ex-2-4.qmd and 2-4-references.bib, and ch2-practice/data holds 2-1-nebraska-yield.csv. If you turned ch2-practice into a website in Ex-2-3, check that note.qmd and ex-2-4.qmd are not in the render: list in _quarto.yml (or are otherwise left out of the website), or the note will be built into the site.

Answers

Open each one only after you have tried the task.

Task 1: Claims and evidence

What a good answer looks like

A and B. For example:

  1. “Average county yields stayed close to 200 bushels per acre from 2014 to 2017”: a figure of the average yield per year, fig-yield-by-year, caption “Average corn yield of Nebraska counties per year, 2014 to 2018.”
  2. “Fewer counties reported in 2018 than in other years”: a table of the number of counties and the average yield per year, tbl-counties, caption “Counties reporting, and their average yield, per year.”

Any claim the data supports is fine, as long as the figure or table shows exactly that claim and has a label with the right prefix.

C. schlenker2009 (Schlenker and Roberts, 2009), lobell2014 (Lobell and six others, 2014), hansen2017 (Hansen and Ortiz, 2017). From their titles: heat and yields, drought sensitivity in the Midwest, and irrigation and the yield gap in Nebraska. At this point nothing about the file looks wrong.

Task 2: Set up the note

What to look for

The header should have bibliography: 2-4-references.bib (the path is from the folder note.qmd is in, so the file name alone), both outputs under format:, and echo: false for the Word version. For example:

format:
  docx:
    echo: false
  html:
    echo: true
    embed-resources: true
bibliography: 2-4-references.bib

If the AI put echo: false under execute: instead, it applies to every format and the HTML hides the code too. Ask for it under docx: only, and echo: true under html:, so you can check the code in the HTML version. Each chunk’s sentence, written as a comment on its first line, then shows with the code in the HTML and stays out of the Word file.

Task 3: A numbered figure and table

What you should find

The numbers behind the two example claims:

Year Counties Average yield (bushels per acre)
2014 51 198
2015 48 204
2016 50 199
2017 47 205
2018 29 213

The check: 225 rows.

Breaking the label. With the chunk labelled plot-... and the sentence still saying @fig-..., the render does not stop. The sentence shows ?@fig-... where “Figure 1” was, and the figure loses its number and its “Figure 1:” in the caption. The render log has a warning, “Unable to resolve crossref”, which is easy to miss among the other lines. Search the output for ?@ every time.

Task 4: Citations

What you should find

Sentence 1 cites schlenker2009, sentence 2 lobell2014, sentence 3 hansen2017. The HTML shows three citations, such as (Schlenker and Roberts 2009), and a reference list with three entries. No ?), because all three keys are in the file.

Everything renders. Nothing so far says anything is wrong.

Task 5: Does every reference exist?

What you should find
Key DOI What opens
schlenker2009 10.1073/pnas.0906865106 The same article: same title, authors, year
lobell2014 10.1126/science.1251423 The same article
hansen2017 10.1093/ajae/aaw088 A different article: Horan and Shortle (2017), “Endogenous Risk and Point-Nonpoint Uncertainty Trading Ratios”, in the same journal, volume and pages

The DOI works, the journal is real, the volume and pages are those of a real article; only the title and the authors do not match. There is no article by Hansen and Ortiz with that title. This is what an invented reference looks like: every part that is easy to check is plausible, and checking only that “the link works” would have passed it.

What to do:

  • In the .bib file: remove hansen2017.
  • In the note: sentence 3 now has no source. Either find a real study that shows it (search for one, read it, and get its entry from the publisher), or remove the sentence. Do not keep a claim because a reference for it once appeared.
  • With your coauthor: tell them which entry was invented and how you found it, so they check the rest of their file.

If you asked the AI whether the entries are real: the answer varies. An AI that cannot look the DOI up may say all three look correct, because they are formatted correctly. An agent that can open web pages may find the mismatch. Either way, its answer is one more thing to check, not the check itself.

Task 6: The Word version

What you should find

The .docx has numbered captions (“Figure 1:”, “Table 1:”), the sentences refer to them by number, there is no code, and the reference list is at the end. If you see code, echo: false is missing for the docx output. If you see ?@, a label was not fixed in Task 3. If the check lines appear in the Word file, hide the check chunk with include: false now that you have read them in the HTML (lecture 02-4, the strong request).

A Word file is an output, like the HTML. If your coauthor edits it, copy their edits back into note.qmd; the next render rebuilds the Word file from the .qmd and their edits would be lost.

Wrap-up

What a good answer looks like

A. None of today’s problems stopped a render. A broken label and an unknown key give warnings in the render log and visible marks (?@, ?)) in the output; an invented reference gives nothing at all. Only reading the output, and opening every DOI, finds them.

B. Get every entry from a record you looked up (the journal’s “Export citation”, the DOI, or Google Scholar’s BibTeX, whose entries usually have no DOI and sometimes have errors, so compare them with the publisher’s page), never from the AI’s memory; and open every DOI before sending the file to anyone.
