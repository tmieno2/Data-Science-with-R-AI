Ex-9-7: Getting Spatial Data from Online Sources, with an AI Assistant

Abstract
Spatial Data

This is an in-class exercise. Before class, work through the lecture 09-7: Getting Spatial Data from Online Sources. In class, you download the data yourself, with an AI assistant writing the code. Your job is everything the AI cannot do: deciding what data the question needs, knowing what should arrive, and judging whether what arrived is that.

Setup

  1. Before class, if you want to do Task 6: request a free USDA-NASS Quick Stats key at https://quickstats.nass.usda.gov/api. It arrives by email, sometimes after a delay. Add a line NASS_API_KEY=your-key to the file .Renviron in your home folder (ask the AI how to open it), then restart R. Never put the key in a .qmd.
  2. Download the worksheet, ex-9-7.qmd. There are no data files to download from here: you download the data in class. The one exception is the fallback file below.
  3. Use the R Project folder ch9-practice from the earlier Chapter 9 exercises, or make one, with two subfolders, data and analysis. Inside data, make a folder raw for downloads. You may ask the AI how to do this.
  4. Copy the worksheet into ch9-practice/analysis.
  5. Ask the AI to install the sf, terra, tidyterra, tigris and prism packages, and rnassqs if you will do Task 6.
  6. Open the worksheet and start at Task 1.
If PRISM refuses the download

PRISM refuses a file downloaded more than twice in a day, which can happen in a class where many people download the same days. If PRISM refuses the download, use this file: 9-7-ppt-kansas.tif. It holds the five days of Task 4, one layer per day, cut to a rectangle a little larger than Kansas. Save it as data/raw/9-7-ppt-kansas.tif and tell the AI to read it instead of downloading.

It worked if

Typing here::here() in the Console prints the path to ch9-practice and nothing longer.

If here::here() prints a path ending in analysis, the .Rproj file was not recognised. here only accepts a .Rproj file whose first line starts with Version:, which every project created in RStudio (File, New Project) has.

The numbers below come from downloads made on 14 November 2026. Sources occasionally revise their data, so yours may differ slightly; a large difference is worth asking about.

Task 3 (if time allows): A map of the contiguous states

What you should find

56 features, not 48 or 50. Besides the 50 states, the file holds 6 more: District of Columbia, American Samoa, Puerto Rico, United States Virgin Islands, Guam, Commonwealth of the Northern Mariana Islands. These are the District of Columbia and the US territories, which the Census Bureau publishes with the states. With Alaska and Hawaii, 8 features are not contiguous states.

Nothing failed: the function returned what the Census Bureau calls “states and equivalent entities”. Only the count check, and the list of names, showed that it was not what you meant. Drawn on a map, the territories and Alaska also stretch the map across the Pacific, which is often how people first notice.

A request that keeps what you need:

From the states layer, keep only the 48 contiguous states: drop Alaska,
Hawaii, the District of Columbia and the territories. Then check: the
number of features (I expect 48), and draw a map.

48 features remain. Whether to keep the District of Columbia is a decision about your map; say which in the request.

Task 4: Daily rain from PRISM

What you should find

5 layers, with the dates 20230710, 20230711, 20230712, 20230713, 20230714 in their names, in NAD83 longitude and latitude, with cells of 0.0417 degrees (about 4 km). Daily values over Kansas range from 0 to 123.4 mm, the largest on 20230713.

The units are not in the raster. They are in PRISM’s documentation, and in the .info.txt file the download saved beside each .bil. That file is where “mm” in your checks comes from.

The blanks, filled in: ppt, 2023-07-10, 2023-07-14, 5, and a range such as 0 to 150 (a single day’s rain above about 150 mm anywhere in Kansas would be extraordinary).

Task 5: Rain in each county

What you should find

105 rows and 0 counties with no value, but one check fails: counties not entirely inside the raster’s rectangle: expected 0, got 1 (Wyandotte).

You cropped the raster to the counties, so how can a county stick out? crop() cuts along cell edges, and by default it rounds the counties’ rectangle to the nearest cell edge. Where the nearest edge lies inside the counties’ rectangle, a sliver of the edge county is cut off: here about 1.4 km of Wyandotte County’s eastern tip, on the Missouri River. Its average comes from the rest of the county, with no NA and no warning.

The fix is to round outward: crop(ppt, counties, snap = "out") keeps every cell any county touches. With it, the same check gives 0. A sliver this small barely moves one county’s average, but the same rounding on a coarser raster cuts off whole cells.

County averages of the five-day total range from 0 mm (Shawnee) to 58 mm (Crawford). Summer rain in Kansas comes from storms, so neighbouring counties can differ a great deal over a few days; compare the county map with the daily maps of Task 4, where the same pattern should be visible.

The checks from lecture 09-6 caught a problem created by your own code, in a step that looked too simple to need checking.

Task 6: Statistics from USDA-NASS

What you should find

The search returns 10 items. The one for all soybeans is SOYBEANS - ACRES HARVESTED; the others are parts of it (irrigated, non-irrigated, double cropped, organic, and so on). Choosing among them is your decision, not the AI’s. At most 105 counties times 3 years, 315 rows, can arrive.

These answers cannot list your exact numbers, because the download needs your own key, and they were written without one: the rnassqs code was not run for this page. The list of items above comes from the tidyUSDA package’s saved list of NASS items. What to look for in your HTML:

  • Fewer rows than counties times years. NASS does not publish a county when too few farms report, and western Kansas grows few soybeans. Count the counties per year and compare with 105.
  • Rows that are not counties. Rows named OTHER (COMBINED) COUNTIES, county code 998, combine the unpublished counties of one district. They are not counties, and must not be mapped or averaged with them.
  • Units and type. unit_desc should say ACRES. Value is acres harvested in the county, not a share, and may arrive as text with commas (12,300) and (D) for withheld values; converting it to a number turns (D) into NA, so ask how many became missing.

If any year is missing entirely, NASS may not have published the survey for that year yet. That is a check on “which years arrived”, which you asked for.
