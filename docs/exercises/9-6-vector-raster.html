Ex-9-6: Vector Meets Raster, with an AI Assistant

Abstract
Spatial Data

This is an in-class exercise. Before class, work through the lecture 09-6: Vector Meets Raster: Cropping, Masking and Extracting Values. In class, you work through the worksheet with an AI assistant writing the code. Your job is everything the AI cannot do: knowing what the raster holds and whether it covers your area, asking for the right checks, and judging whether the result is right.

Setup

  1. Download the worksheet, ex-9-6.qmd, and the data files:
    • 9-6-ndre.tif, 9-6-treatment-blocks.gpkg and 9-6-corn-yield-points.gpkg
    • 9-6-co-counties.gpkg and 9-6-ppt-2012aug.tif
    • 9-6-README.txt
  2. Use the R Project folder ch9-practice from the earlier Chapter 9 exercises, or make one, with two subfolders, data and analysis. You may ask the AI how to do this.
  3. Copy the six data files into ch9-practice/data, and the worksheet into ch9-practice/analysis.
  4. Ask the AI to install the sf, terra and tidyterra packages if you have not already.
  5. Open the worksheet and start at Task 1.
It worked if

Typing here::here() in the Console prints the path to ch9-practice and nothing longer.

If here::here() prints a path ending in analysis, the .Rproj file was not recognised. here only accepts a .Rproj file whose first line starts with Version:, which every project created in RStudio (File, New Project) has.

Answers

Open each one only after you have tried the task.

Task 1: Look at the drone image and the field

What you should find

A. No. The raster is in WGS 84 (longitude and latitude); the plots and points are in WGS 84 / UTM zone 15N (metres). Transform the vector layers to the raster’s CRS: transforming a raster recomputes every cell and loses detail, transforming points and polygons does not.

B. A cell is about 1.8 m by 1.8 m (the cell size is printed in degrees; the AI can convert it). A plot is roughly 24 m across if it were square (the plots are long strips, so their real widths differ). So a plot covers a few hundred cells.

C. Yes: all 25 plots (25 inside the raster’s rectangle) and all 3,830 yield points (3,830).

Task 2: NDRE at each yield point

What you should find

3,830 rows, one per point; 0 points with a missing value; values from 0.51 to 0.64, inside the raster’s own range of -0.14 to 0.7.

The blanks, filled in: EPSG 4326 (WGS 84 longitude and latitude), 3830, 0 (Task 1C showed every point inside the raster), and the raster’s range from Task 1.

If the AI did not transform the points first, the HTML shows the warning [extract] transforming vector data to the CRS of the raster, and the values are still right. Asking for the transformation keeps the code saying what it does.

Task 3: Average NDRE in each plot

What you should find

25 rows, no plot without a value, every plot inside the raster, and the smallest plot covers 204 cells. With so many small cells per plot, the cell-counting rule barely matters: the default rule (cell centre inside) and the weighted rule differ by at most 0.001 in any plot.

Mean of the plot averages by nitrogen rate:

target_rate mean_ndre
105 0.605
135 0.611
165 0.608
195 0.611
215 0.610

The largest difference between rates is 0.006, while NDRE at the yield points (Task 2) varies across the field with a standard deviation of 0.015. Whatever relation there is between nitrogen and greenness here is small next to the variation across the field, which is worth knowing before reading anything into the order of the five numbers.

Task 4: Rain in Colorado’s counties

What you should find

64 rows, but the checks fail:

  • 59 counties have no value.
  • Only 3 of the 64 counties lie entirely inside the raster’s rectangle.
  • 2 more counties have a value but are only partly covered: Weld, Yuma.

The colleague’s file was made for a Nebraska project. It covers latitudes from 39.98 degrees north up to Nebraska’s northern border, and Colorado runs from 37 to 41 degrees north. So the raster covers only a narrow strip along Colorado’s northern border, which the map with the raster’s rectangle shows at once.

Which values to use:

  • The 3 counties entirely inside the raster: usable.
  • The 59 counties with no value: nothing to use, and the NA says so.
  • The 2 partly covered counties: do not use. Their value is the average over their northern edge only, and nothing in the number says so. This is the silent failure of the task.

Next step: download PRISM for Colorado and the same days (lecture 09-7), and extract again. The check “counties not entirely inside the raster’s rectangle” is the one to keep in every extraction request.

Task 5: Maria’s code

Answers

A. Reads the raster; reads the plots; keeps the five plots of replication 1; extracts their mean NDRE, after transforming them to the raster’s CRS; merges the values onto all plots, treating ID as block_id.

B. ID is the row number within rep1: 1 to 5. The replication-1 plots have block_id 21, 22, 23, 24, 25. So the merge puts the five values on plots 1, 2, 3, 4, 5, which are replication 2, and leaves the five plots she wanted empty.

C. Both pass: 5 plots have a value and 20 have none. The counts are exactly right; the plots are wrong. A count cannot tell one plot from another.

D. A check on which plots got a value: “replication of the plots with a value: expected 1, got 2”, or “block_id of the plots with a value: expected 21, 22, 23, 24, 25”. Line 5 should first turn ID into the plots’ own IDs, block_id = rep1$block_id[ID], and then merge by block_id, as on the lecture’s polygon example.

E. The AI usually explains that ID is a row number when asked how values are matched back. Compare its list with yours.
