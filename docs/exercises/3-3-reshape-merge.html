Ex-3-3: Reshaping and Merging, with an AI Assistant

Abstract
Data Wrangling

This is an in-class exercise. Before class, work through the lecture 03-3: Reshaping and Merging. In class, you work through the worksheet with an AI assistant writing the code. Your job is everything the AI cannot do: knowing what the files contain, asking for the right thing and the right checks, and judging whether the result is right.

Setup

  1. Use the ch3-practice project from Ex-3-1. If you do not have it, make an R Project folder called ch3-practice with two subfolders, data and analysis (you may ask the AI how).
  2. Download the worksheet, ex-3-3.qmd, and the data files 3-3-corn_yield_wide.csv and 3-3-drought.csv.
  3. Copy both data files into ch3-practice/data, and the worksheet into ch3-practice/analysis.
  4. Open the project, open the worksheet, and start at Task 1.
It worked if

Typing here::here() in the Console prints the path to ch3-practice and nothing longer.

The two files are a teaching dataset, built from US Department of Agriculture county yields and the US Drought Monitor. One problem has been put into one of them on purpose; finding it is part of the exercise.

Answers

Open each one only after you have tried the task.

Task 1: Read and look

What you should find

A. One row is one county. The year is in the column names: yield_2014, yield_2015, yield_2016, yield_2017, yield_2018. yield_wide has 116 rows and 8 columns.

B. One row should be one county in one year, identified by fips and year. drought has 331 rows.

C. yield_wide uses two columns, state_name and a 3-digit county_code. drought uses one, fips: 5 digits, the 2-digit state code followed by the same 3-digit county code. So Baca County, Colorado is Colorado and 009 in one table and 08009 in the other. The keys have to be made the same before merging; the AI cannot know that unless you tell it how they relate.

D. 264 of the 580 yield cells are missing. Those county-years are absent from the source: county yields are not published for every county in every year (for example, when too few farms report). In the wide layout, every county gets a cell for every year, so an absent county-year shows up as a missing value.

Task 2: Wide to long

What you should find

Prediction. Keeping missing yields: 116 counties × 5 years = 580 rows. Dropping them: 580 − 264 = 316 rows. The total of all yields is 63,094.9 before and after.

Result. 316 rows, no missing values, year a whole number, and the totals match.

The blanks, filled in: one row is “one county”, the columns are yield_2014, yield_2015, yield_2016, yield_2017, yield_2018, and one row of the result is “one county in one year”.

If year came back as text such as "yield_2014", the request’s “Turn year into a whole number” was not followed; the type check shows it. A text year would also make the merge in Task 4 stop with an error, since year is a number in drought.

Task 3: Look at the keys

What you should find

Prediction. None in either table: each should have one row per county and year.

Result. yield_long has none. drought has 331 rows but only 316 distinct fips-year pairs: 15 pairs appear twice.

A. Every repeated row is from state code 20 (Kansas) in 2016: every Kansas county in that year appears twice. A whole state and year repeated together suggests how the file was put together, for example from two downloads that overlapped by one year.

B. They are exact copies: the same weeks in both rows. Exact copies can be reduced to one row each without losing anything. If the values had differed, you could not pick one without knowing which is right; that would be a question for whoever produced the file, not something to settle in code.

C. 331 rows instead of 316. Each of the 15 Kansas counties with a 2016 yield would appear twice, so any average over county-years would count Kansas 2016 twice. No warning: dplyr warns only when rows repeat on both sides of the match.

Task 4: Merge

What you should find

Prediction. 316 rows, the same as yield_long. After the copies are removed, drought has 316 county-years, the same number as yield_long, so if the keys are built correctly every row of each should match: 0 unmatched rows on both sides.

Result. 316 rows; no repeated keys after the copies are removed; 0 unmatched rows of yield_long and 0 of drought.

The middle blank, filled in, reads something like: “In yield_long, build a fips column by putting the state code (Colorado 08, Kansas 20, Nebraska 31) in front of county_code, as text. In drought, the rows for Kansas in 2016 appear twice as exact copies; keep one of each.”

The sentence above the key-building chunk. If the AI looked up state codes itself, check them against the three you gave it. A wrong code, or a county_code that had lost its leading zeros (9 instead of 009), makes whole states fail to match; the unmatched-rows check shows it as a number far above 0.

The relationship option did its job only because you dealt with the copies first. Run the merge on the original drought and the code stops with an error, which is the point of asking for it.

Task 5: Long to wide, for a report (if time allows)

What you should find

Prediction. 3 rows (one per state) and 6 columns (the state and 5 years). No missing cells: each state has at least one county with a yield in every year.

Result.

state_name 2014 2015 2016 2017 2018
Colorado 187.4 181.0 172.6 206.0 174.8
Kansas 195.2 204.7 182.7 190.7 201.9
Nebraska 197.9 204.1 199.3 205.3 213.2

And the number of counties behind each average:

state_name 2014 2015 2016 2017 2018
Colorado 2 3 8 2 3
Kansas 16 12 15 18 12
Nebraska 51 48 50 47 29

The averages are not equally trustworthy. The smallest number of counties behind an average is 2, for Colorado 2014 and Colorado 2017, while Nebraska’s averages rest on dozens. Which counties report a yield also changes from year to year, so a change in a state’s average can come from a change in which counties are included, not from a change in yields. A note under the table should give the number of counties behind each average, or the table should include report_n.

Task 6: Kim’s code

Answers

A. Reads the drought file; keeps the rows of yield_long whose fips appears in drought, adding the drought columns.

B. read.csv() reads fips as a number, so 08009 becomes 8009. The join then stops with an error, because fips is text in yield_long and a number in drought. If the AI “fixes” that by turning the number back into text, Colorado’s codes are "8009" and so on, which match nothing, and inner_join() drops all 18 Colorado rows without a message.

C. year. Each county-year row of yield_long matches every year of that county in drought, so a county with 5 years in each becomes 25 rows. Because fips repeats in both tables, dplyr prints a warning about a “many-to-many relationship”.

D. Rows before and after (both problems), repeated keys (C: with fips alone as the key, almost every key repeats), unmatched rows (B: all Colorado rows unmatched), and the type of fips in each table (B).
