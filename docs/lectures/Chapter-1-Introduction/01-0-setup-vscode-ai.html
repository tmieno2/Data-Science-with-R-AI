In this course an AI agent writes most of the code, and we work in a way we recommend for your own research too: the agent writes its code into a Quarto document (a .qmd file) and renders it to an HTML page, and you judge the work by reading that page. Lecture 02-1 explains how Quarto works. It is not the only way to work with AI, but it is a good one, and every exercise in this course practises it.

This lecture sets up the computer for that way of working. By the end you will have:

  1. VS Code, the program where all of it happens
  2. An AI agent inside VS Code: Claude Code or OpenAI’s Codex
  3. R, Python and Quarto, installed by the agent at your request, and checked by you
  4. A project folder that the agent and R both recognise

You will not learn the install commands. The agent knows them. What it cannot know is your computer, what you want installed, and whether the result works; those are your part:

The concept

One window for the whole loop

  • What is in the window
  • An agent, not a chat window

VS Code (Visual Studio Code, a free editor from Microsoft) holds everything the research loop needs in one window:

Part of the window What it shows
Explorer (left side) The files and folders of your project
Editor (middle) The file you are reading, such as a .qmd
Preview (beside the editor) The rendered HTML page
Terminal panel (bottom) A terminal: a place where typed commands run. A render’s messages, and its errors, appear here
Agent panel (side) The conversation with Claude Code or Codex

Screenshot to add: the VS Code window with a project open in the Explorer, a .qmd in the editor, its HTML in the preview beside it, the Terminal panel at the bottom, and the agent panel at the side, each part labelled.

A chat window (claude.ai or chatgpt.com in a browser) sees only what you paste into it. It cannot open your files, run anything, or render your document.

An agent (an AI that works inside a folder on your computer) can:

  • read the files of your project, so it sees your actual .qmd and data, not your description of them
  • change files: write code into the .qmd, create files
  • run commands in a terminal: install software, render the document, read the error

That is why the setup in this lecture can be done by the agent. It is also why the next part of this deck is about what you let it do.

Note

The way of working stays the same with either kind of AI: the AI writes the code into a .qmd and renders it, and you judge the HTML, not the chat. Lecture 02-1 teaches it in full on the slide “Working with AI on your own research”.

What has to be on your computer, and why

For Quarto to run R and Python code, these pieces must be installed and must be able to find one another:

Piece What it is Needed for
R The program that runs R code Every R code chunk (a block of code inside a .qmd)
Python The program that runs Python code Python chunks, when you need one
Quarto The program that renders a .qmd into HTML. VS Code needs it installed separately Every render
The Quarto extension for VS Code Adds the Preview button and .qmd support to VS Code Rendering from inside VS Code
rmarkdown and knitr (R packages) The part of R that Quarto uses to run R chunks Any .qmd with an R chunk
here (R package) Builds file paths that start from the project folder Paths in your code (lecture 03-1)
reticulate (R package) Lets R run Python chunks A .qmd with both R and Python chunks
jupyter (Python package) The part of Python that Quarto uses to run Python chunks A .qmd with only Python chunks

Which one runs your document: if a .qmd has at least one R chunk, Quarto runs the whole document through R (with knitr), and any Python chunk in it goes through reticulate. If it has no R chunk, Quarto runs the Python chunks with jupyter.

Note

This course writes its code in R. Python is set up so that Quarto can run it when you need it; you will not learn Python here.

What the agent sends

Everything the agent reads, including your data files, is sent to Anthropic’s or OpenAI’s servers. Do not open a folder holding data you are not allowed to share (data under a confidentiality agreement, a manuscript you are reviewing) until you know your account’s terms allow it.

What the agent may do

How the agent asks for approval

An agent proposes an action (run a command, change a file) and, depending on its permission mode (the setting that decides which actions it must ask you about first), either waits for your approval or goes ahead.

  • Choose the mode
  • What a file change looks like

While you are learning, choose the mode that asks most often. Each request for approval shows you what the agent was about to do, and that is how you learn what it does.

Agent Mode to choose What it asks about
Claude Code Manual Asks before most actions that change files, run commands, or use the internet. Reading files does not need approval
Codex Ask for approval Asks before changing files outside the project folder and before using the internet

Claude Code starts in a mode called Auto, in which a separate AI model reviews most actions and approves them without asking you. Switch it to Manual: click the mode name at the bottom of the box where you type. In Codex, the same choice sits in the permissions control below the box where you type.

Screenshot to add: the Claude Code mode menu open, with Manual selected; and the Codex permissions menu open, with Ask for approval selected.

When an agent changes a file, VS Code shows the old and new versions side by side: removed lines marked in red, added lines in green. This view is called a diff (short for difference).

  • Claude Code in Manual mode shows the diff before the change is made, and waits for you to accept or reject it.
  • Codex shows its changes for you to keep or undo.

Read the diff, not the agent’s summary of it. The summary says what the agent meant to do; the diff is what is now in your file.

Screenshot to add: a diff of a .qmd in VS Code, with one removed line in red and two added lines in green, and the accept and reject buttons.

What to approve, what to read first, what to refuse

The agent asks to What to do
Install a program or package you asked for Read the name; approve if it is on your list
Change a file your request was about Read the diff, then approve or reject
Run a script downloaded from the internet (a line containing curl or irm followed by a web address) Read the web address first: approve only if it is the official site of what you asked to install
Change a settings file of your computer that you did not ask about Ask the agent what the change does and why, before approving
Run a command that starts with sudo (macOS), or that needs administrator rights (Windows) Approve only if you understand what it installs. The slide “What only you can tell it” says how to give your password. Never type a password into the agent panel
Delete files (commands with rm, del or Remove-Item) Never approve without knowing exactly which files and why
Change anything outside your project folder, or your raw data files Never approve without understanding it. Ask what it is for

Important

If an approval request offers to stop asking about that kind of action from now on, decline while you are learning. A request you understand takes two seconds to approve; an action you never saw cannot be checked.

Your turn: four approval requests

You asked the agent to install the R packages rmarkdown and knitr. It then asks to run each of these, one at a time:

A.  Rscript -e 'install.packages(c("rmarkdown", "knitr"))'

B.  /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

C.  rm -rf data

D.  Edit data/yields.csv: replace every "." with "NA"
  • Questions
  • Answers

For each: approve, read first, or refuse? What would you ask the agent?

A. Approve. It installs the two packages you asked for, and nothing else.

B. Read first. It downloads a script from the internet and runs it. The address belongs to Homebrew (a widely used program that installs other programs on a Mac), so it is the official installer. But you did not ask for Homebrew: ask the agent why it needs it, and approve only if the answer makes sense.

C. Refuse. rm -rf data deletes the folder data and everything in it, without asking again and without a way back. Nothing in your request needed it. Ask the agent why it proposed it.

D. Refuse. It edits a data file, which your request was not about. A raw data file is never changed; a change to the data belongs in the .qmd, where the reader sees it.

The project folder

One folder per project

  • Open a folder, not a file
  • How R finds the project folder
  • The instruction file

Each project lives in one folder, with everything in it: data, .qmd files, outputs. You opened it with File, Open Folder (slide “Make and open the project folder”).

  • The agent works on the folder you opened. It reads, changes and runs things there.
  • Open a subfolder by mistake and the agent sees only that subfolder.
  • For a new project, make a new folder and open it; do not put two projects in one folder.

Lecture 03-1 builds every file path with here::here(), which starts from the project folder, whichever subfolder the .qmd is in. To do that, the here package starts at the folder R is working in and moves up, one folder at a time, until it finds a folder that contains a marker (a file or folder that says “this is the top of a project”).

here accepts several markers, among them:

Marker Made by
A file named .here You, or the agent: an empty file made only for this purpose
A file ending in .Rproj RStudio, which this course does not use
A file _quarto.yml A Quarto website or book project
A folder .git git, the version control program (lecture 06-2)
A folder .vscode with a settings.json in it VS Code, when you change a setting for one folder

The nearest folder holding any marker wins. In VS Code there is no .Rproj file, so the project setup creates an empty .here file at the top of the project folder.

Note

Files whose names start with a dot, such as .here, are hidden by Finder and File Explorer. VS Code’s Explorer shows them.

An instruction file is a plain-text file at the top of the project folder that the agent reads at the start of every session, without being asked. It holds what the agent cannot know by looking at the files:

  • what the project is about, in two sentences
  • which files must never be changed (for example, the raw data)
  • facts about the data: units, what one row is, codes for missing values

Its name is AGENTS.md. Codex reads AGENTS.md. Claude Code reads it too, but only when the project has no CLAUDE.md (Claude Code’s own name for the same file), and only from Claude Code version 2.1.277 on. So one AGENTS.md serves both agents.

Keep it short, and write each rule as a plain instruction (“Never change any file in data/raw/”). The agent treats it as information, not as a lock: it can still miss a rule, which is why you still read every diff.

Asking the agent to set up

What only you can tell it

The agent knows how to install R, Python and Quarto on every common system, and it finds out which system your computer runs (check that it got it right when it says). What it does not know:

  1. What you want installed: the list on the slide “What has to be on your computer, and why”. Without the list, it installs what it guesses a data scientist needs.
  2. That you want to approve each step, with a one-sentence reason, so the approval requests mean something to you.
  3. That the pieces must find one another: the Python where jupyter goes must be the one Quarto uses, and reticulate must use it too. If nothing tells it otherwise, reticulate builds a separate Python of its own. Two Pythons on one computer is the most common cause of a setup that looks finished and then fails.
  4. How you will check it: quarto check (a command that reports which pieces Quarto can find) and the test documents of the setup checklist page.

Your password

On a Mac, a command that needs your password must be run by you: Terminal, New Terminal, paste the command the agent gave you, and type the password there. On Windows, a window asks whether to allow the change; allow it only for a program on your list. Never type a password into the agent panel.

Checking the setup

Check 1: quarto check

The agent says it is done. That is a report, not a check. Quit VS Code completely and reopen it (so it sees the newly installed programs), then run quarto check yourself: Terminal, New Terminal, type quarto check, press Enter. Read the output section by section.

  • What to look for
  • What a failure looks like
Section of the output It worked if
Checking Quarto installation OK, with a version number
Checking Python 3 installation OK, and the line Jupyter: followed by a version number
Checking Jupyter engine render OK (Quarto rendered a test document through Jupyter). This line appears only when Jupyter is found
Checking R installation OK, and lines knitr: and rmarkdown: each followed by a version number
Checking Knitr engine render OK (Quarto rendered a test document through R)

Note the Path: line in the Python section: it is the Python Quarto uses. Check 2 compares against it.

This is real output from a computer on which Python is installed but jupyter is not (cut down to the Python section):

[✓] Checking Python 3 installation....OK
      Version: 3.15.0
      Path: /opt/homebrew/opt/python@3.15/bin/python3.15
      Jupyter: (None)

      Jupyter is not available in this Python installation.
      Install with python3 -m pip install jupyter

The section still says OK, because Python itself was found. Only the Jupyter: (None) line shows the problem, and the line Checking Jupyter engine render is missing. Read every line of a section, not only its tick.

Check 2: render the test documents

quarto check says the pieces are installed. Only a render shows that they work together. The setup checklist page, Ex-1-0, has two short test documents to download into your project folder.

  • What each one shows
  • Why these answers

The R and Python test has two R checks, the project folder’s path, and one Python chunk. Its HTML should show:

R runs: expected 55, got 55
.here file in the project folder: expected TRUE, got TRUE
project folder: <the folder you opened in VS Code>
Python runs: expected 55, got 55
Python used: <the same path as quarto check's Python Path line>

The Python-only test has no R chunk, so Quarto runs it with jupyter. Its HTML should show:

Python runs through Jupyter: expected 55, got 55
Python used: <the same path as quarto check's Python Path line>
  • 55 is the sum of the numbers 1 to 10: an answer known before rendering, so a wrong or missing number means the language did not run.
  • TRUE means here found the .here file, so paths built with here::here() start in the right folder.
  • The Python used path must match quarto check. If it does not, R is using a different Python from the one that has jupyter, and a package installed in one is missing in the other.

The Quarto loop in VS Code

Render, read the HTML, read the error

  • Render
  • Where errors appear
  • Send the error to the agent

With a .qmd open in the editor, click Preview at the top right of the editor, or press Cmd + Shift + K (Mac) / Ctrl + Shift + K (Windows).

Quarto renders the document and shows the HTML in a panel beside the .qmd. The HTML file itself is written next to the .qmd, so you can also open it in a web browser.

Screenshot to add: a .qmd open in VS Code with the Preview button circled, and its rendered HTML in the panel beside it.

The agent can render too: it runs the render in its own terminal and tells you the result. Either way, you read the HTML.

The render runs in the Terminal panel at the bottom of VS Code, and prints its messages there. If a chunk fails, the last lines say which:

Error:
! object 'farms' not found
Quitting from report.qmd:6-9 [count-farms]

The line starting with ! is R’s own error; Quitting from names the file, the lines and the chunk. When a render fails, no new HTML is written, so the preview still shows the old page. Look at the Terminal panel before trusting the preview.

Screenshot to add: the Terminal panel after a failed render, with the error lines visible and the out-of-date preview beside the editor.

The agent may not have seen your render. Copy the error lines into the agent panel, and say that the fix must go into the .qmd. Then render again yourself: the document is fixed when it renders, not when the agent says it is.
