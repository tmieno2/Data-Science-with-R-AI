03-1: Getting Data In and Out of R

How this lecture works

What you will and will not learn today

  • The plan
  • Directions

An AI assistant can write the code that reads a file into R. It knows every function and every argument. What it cannot do is:

  • see the files on your computer
  • know what is inside them
  • know what the data is for
  • tell whether the result is right

Those four are your job. So today is about:

  1. The concept: what importing and exporting are, and what has to be true for them to work
  2. Reading code: recognising what a line of import code does, without memorising it
  3. Asking AI: what to put in your request
  4. Checking: how to tell whether the code the AI wrote did the right thing
  • Clone this repository, which holds the datasets used here
  • Ask your AI assistant to install the tidyverse and haven packages if you have not already. Installing is a one-time step per computer (see the packages slide in Chapter 1).

The concept

What importing is

A data file is a table saved on disk in some format. Importing means a function reads that file and builds a table inside R (a data frame) that you give a name to.

Every import line you will see has the same three parts:

corn <- read_csv("corn_yields.csv")
Part Here What it is
Name corn What you will call the table inside R. <- stores the result under that name.
Reader read_csv The function that understands this file’s format
Path "corn_yields.csv" Where the file is

The AI will pick the reader and fill in the details. You need to be able to look at a line like this and say which part is which.

What has to be true for an import to work

  • The four conditions
  • Loud and silent failures
  1. R can find the file. The path points at a file that exists.
  2. The reader matches the format. A csv reader for a csv file, an Excel reader for an Excel file.
  3. The reader understands the layout. Where the column names are, which sheet to read, what marks a missing value.
  4. Each column gets the right type. Numbers as numbers, text as text, IDs kept exactly as written.
  • If condition 1 or 2 fails, R stops with an error. Annoying, but you know something is wrong.
  • If condition 3 or 4 fails, R gives you a data frame with no error, and the data frame is wrong.

Important

The silent failures are why checking matters. Code that runs is not the same as code that is right.

Condition 1: R can find the file

  • Paths
  • The project root and here()
  • Why AI gets this wrong

A path is the address of a file. There are two kinds:

  • Absolute path: starts at the top of the disk, for example "/Users/taro/Documents/class/corn_yields.csv". It works only on the computer it was written on, because nobody else has those folders.
  • Relative path: starts from the folder R is currently in (the working directory), for example "data/corn_yields.csv". It works on any computer that has the same project folder.

What R treats as the working directory:

  • At the Console: your project folder (if you opened an R Project)
  • Inside a .qmd file: the folder the .qmd is saved in

The safest path is one measured from the top of your project folder (the project root). The here package does that. Recognise it when you see it:

corn <- read_csv(here::here("data", "corn_yields.csv"))

This reads data/corn_yields.csv inside your project, whichever subfolder your code is in and whoever’s computer it runs on.

The AI cannot see your folders, so it guesses the path. Its guesses tend to be one of these:

  • just the file name, assuming the file is in the working directory
  • an absolute path copied from an example, such as "C:/Users/yourname/..."
  • setwd(...) to change the working directory first

All three break as soon as the code runs somewhere else. Tell it where the file is (see “Asking AI” below).

Condition 2: the reader matches the format

The file extension (the part after the last dot) tells you the format. You do not need to memorise the reader; tell the AI the extension and it will pick one. You do need to recognise them:

Extension Format Reader you will see What the file remembers
.csv plain text, any software opens it read_csv() (readr) Only text. Types are guessed on reading.
.xls, .xlsx Excel workbook read_excel() (readxl) Several sheets per file
.dta STATA read_dta() (haven) Types and variable labels
.rds R’s own format readRDS() (built in) The exact R object, nothing guessed

Note

A csv file stores everything as text, so the reader has to guess each column’s type. That guessing is where conditions 3 and 4 go wrong.

Conditions 3 and 4: the silent failures

  • Lost leading zeros
  • Codes for missing values
  • The wrong sheet

County codes (FIPS) for Alabama start with 0. Here is a tiny csv, written straight into the code, and what the reader makes of it:

small_csv <- "fips,county,yield
01001,Autauga,150
01003,Baldwin,-999
31019,Buffalo,173"

small <- read_csv(I(small_csv), show_col_types = FALSE)
small$fips
[1] "01001" "01003" "31019"
read.csv(text = small_csv)$fips
[1]  1001  1003 31019

The two readers guessed differently about the same file. read_csv() kept 01001 as text. read.csv(), the built-in reader that AI assistants often write, decided the column was a number and turned 01001 into 1001. No error either way. Later, joining that table to another one by fips would quietly fail to match these counties.

The same file uses -999 to mean “no data”, a common convention. The reader does not know that:

mean(small$yield)
[1] -225.3333

An average yield of -225.3 bushels per acre. Again no error. The reader has to be told that -999 means missing.

corn_yields.xls has two sheets:

readxl::excel_sheets("corn_yields.xls")
[1] "corn_yields_08" "corn_yields_09"

A reader told nothing about sheets reads the first one only. If you wanted both years, you now have half the data, with no error.

Asking AI

What to put in your request

The AI already knows the functions. Your request supplies what it cannot know:

  1. The file: its name, its format, and where it sits inside your project
  2. What is inside: the first few lines, the sheet names, and anything unusual (IDs with leading zeros, codes for missing values)
  3. What you want back: the name of the table, what one row is, and which type each key column should be
  4. Your project’s rules: for example, use the tidyverse, build paths with here::here(), never setwd() or absolute paths
  5. Ask for checks: have it print the numbers you will check against (next section)

Using an agent in your editor or terminal?

An agent such as Claude Code can open the file and look for itself. Still write down what you expect (number of rows, types of key columns) before it runs, so you have something to compare against.

Look at the file before you ask

  • Why
  • Raw first lines of a csv
  • Counting lines

You cannot describe a file you have not looked at, and you cannot check an import without knowing what the file holds. Two ways to look:

  • Open it: a csv in a text editor, an Excel file in Excel
  • Ask R to show the raw first lines, before any reader has guessed anything
readLines("corn_yields.csv", n = 3)
[1] "Year,State,FIPS,County_name,State_name,Commodity,Data item,Irrigated,Yield"                         
[2] "2008,31,31019,BUFFALO,NEBRASKA,CORN,\"CORN, GRAIN - YIELD, MEASURED IN BU / ACRE\",0,173"           
[3] "2008,31,31019,BUFFALO,NEBRASKA,CORN,\"CORN, GRAIN, IRRIGATED - YIELD, MEASURED IN BU / ACRE\",1,182"

From this you learn: the first line is column names, values are separated by commas, FIPS is a 5-digit code, one column name (Data item) has a space in it.

length(readLines("corn_yields.csv"))
[1] 162

162 lines, one of which is the column names. So a correct import has 161 rows. Write that number down before you import.

A weak request and a strong one

  • Weak
  • Strong
  • What came back
Read my corn data into R.

The AI has to guess the file name, its location, its format, its layout and what you want. A typical reply:

setwd("C:/Users/yourname/Documents")
corn <- read.csv("corn.csv")

It runs on nobody’s computer as written, and if you fix the path, it still guesses every type.

In my R project, the file data/corn_yields.xls is an Excel workbook with
two sheets, corn_yields_08 and corn_yields_09 (one per year). Each row is
one county, one year, and one irrigation status.

Write R code (tidyverse) that:
- reads BOTH sheets and stacks them into one table called corn
- keeps FIPS as text so leading zeros survive
- builds the path with here::here(), no setwd() and no absolute paths

Then print: the number of rows from each sheet, the number of rows in
corn, the type of every column, and the number of missing values in
each column. Explain each line in one sentence.

A version of what an AI returns for the strong request. Read it line by line; you should be able to say what each line does:

library(readxl)
library(dplyr)

path <- here::here("data", "corn_yields.xls")

corn_08 <- read_excel(path, sheet = "corn_yields_08", col_types = "text")
corn_09 <- read_excel(path, sheet = "corn_yields_09", col_types = "text")

corn <- bind_rows(corn_08, corn_09) |>
  mutate(Year = as.integer(Year), Yield = as.numeric(Yield))

c(nrow(corn_08), nrow(corn_09), nrow(corn))
glimpse(corn)
colSums(is.na(corn))

bind_rows() stacks one table on top of another; you will meet it properly later in this chapter.

Checking the result

Checking: what to ask for, and why

  • The five checks
  • Asking for them
  • Reading the answer

The AI can write the checking code. It cannot decide which checks your file needs, and it cannot know the right answers. Ask for these after every import:

Ask the AI to print Why What only you can supply
1 the number of rows and columns Rows go missing or appear when the wrong sheet is read or a title line is read as data the row count from looking at the file
2 the type of every column A wrong guess (an ID read as a number, a number read as text) gives no error which type each key column should be
3 the number of missing values in each column A missing-value code the reader was not told about, such as -999, is kept as a real value how the file marks missing values
4 the smallest and largest value of each numeric column Impossible values expose those codes, and unit mistakes what range is believable
5 the first row Shifted or merged columns show up at once the same row in the raw file

One sentence at the end of your request does it:

After reading the file, print: the number of rows and columns, the type of
every column, the number of missing values in each column, the smallest and
largest value of each numeric column, and the first row.

Better still, tell it what you expect, so the output says which checks failed:

I expect 161 rows, 9 columns, no missing values, and Yield between 100 and
250. Print a clear message for every expectation that is not met.

The second version only works if you looked at the file first. That is the part you cannot hand off.

The AI writes the code. You read what it prints and compare it with what you expected:

Code the AI wrote 
list(
  rows_and_columns  = dim(corn),
  column_types      = sapply(corn, class),
  missing_per_column = colSums(is.na(corn)),
  yield_range       = range(corn$Yield)
)

[1] 161   9

$column_types

  "numeric"   "numeric"   "numeric" "character" "character" "character"

"character"   "numeric"   "numeric"

  • 161 rows: the file has 162 lines, one of them column names. Matches.
  • FIPS is a number. Fine here, since every Nebraska code starts with 31, but in a national dataset this is the column that loses leading zeros.
  • No missing values, and yields from 103 to 204 bushels per acre: believable.

Checks that come from knowing the data

The five checks apply to any file. The most useful checks come from what you know about this data, and no AI will think of them for you.

The two sheets of corn_yields.xls are labelled 2008 and 2009. Yields change from year to year, because the weather does. So ask:

Read both sheets of corn_yields.xls and tell me whether each county's
yield is the same in both years.
Code the AI wrote 
yield_08 <- readxl::read_excel("corn_yields.xls", sheet = "corn_yields_08")
yield_09 <- readxl::read_excel("corn_yields.xls", sheet = "corn_yields_09")

identical(yield_08$Yield, yield_09$Yield)
[1] TRUE

TRUE: every county has exactly the same yield in both years. The code ran without error, and the row counts and types pass. The problem is in the file itself, and only a question based on what real yields look like found it.

Your turn: read the AI’s code

setwd("C:/Users/jsmith/Desktop/class")

mean(corn$Yield)

  • Answers

A. What does each of the four lines do?

B. Which line will fail on your computer, and why?

C. Which problem would give a wrong answer without an error?

D. Rewrite the request so the AI could not make these mistakes.

A. Changes the working directory; loads readxl; reads the workbook into corn; averages the Yield column.

B. Line 1. The folder C:/Users/jsmith/... exists only on jsmith’s computer.

C. Line 3 reads only the first sheet, so the average covers 2008 only. Nothing says so.

Exporting

What exporting is

Exporting is importing in reverse: a function writes a table from R into a file. The line has the same parts, in the order object first, then path:

write_csv(corn, "corn_clean.csv")

The decision that is yours is the format, and it depends on who reads the file next and what has to survive:

Format Choose it when What is lost
csv anyone, in any software, must be able to read it every type: dates, factors and text IDs come back as guesses
rds you, in R, will read it in the next step of the project nothing, but only R can open it
dta a collaborator uses STATA some R-only types

A reasonable default

Keep raw data as you received it. Save intermediate results as rds, so types survive from one script to the next.

Checking an export: the round trip

Why: a file can quietly keep less than you saved. The only way to know what it kept is to read it back.

What to ask: “Save the table, read it back, and compare it with the original.” Here Irrigated was first made a factor (a column of categories), then saved as csv and as rds:

Code the AI wrote 
corn_f <- mutate(corn, Irrigated = factor(Irrigated, labels = c("no", "yes")))

csv_file <- file.path(tempdir(), "corn.csv")
rds_file <- file.path(tempdir(), "corn.rds")
write_csv(corn_f, csv_file)
saveRDS(corn_f, rds_file)

class(read_csv(csv_file, show_col_types = FALSE)$Irrigated)
[1] "character"
Code the AI wrote 
class(readRDS(rds_file)$Irrigated)
[1] "factor"

The csv gave back text: the factor was lost. The rds gave back the factor.

A full request

“Save corn as data/corn_clean.rds using here::here(), then read it back and tell me whether it matches the original exactly, and if not, which columns differ.”
